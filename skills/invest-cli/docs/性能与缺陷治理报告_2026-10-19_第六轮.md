# 第六轮：探测相位去重库 + 搜索结果落盘 + 两道静态门禁（2026-10-19）

## 0. 一句话

三条改动，两条是「删掉白付的成本」，一条是「补上一类静态拦截」：

- `mx-data` 判「美股依赖装没装」本来用 `import yfinance`，连带 pandas/numpy；
  换成 `find_spec` 后，缓存命中路径 **351.5ms → 36.0ms**、RSS **81MB → 14MB**。
- 同花顺 `tickers/search`（代码/名称 → thscode）结果落盘 24h，快照过期重取时
  **stock 0.58 → 0.44s、fund 0.60 → 0.46s**（中位，n=5）。
- 同一行 `zip(strict=True)` 让系统 3.9 上 6 条测试红了两天；现在有语法门 + API 门，
  另有 `urllib` 子模块门盖住两次静默降级事故的整类。

## 2. 改动与归因

### 2.1 `mx-data` 探测相位不 import 重库（`_ensure_runtime`）

```python
# 前：判据是「真 import 得到吗」
try:
    import yfinance  # 连带 pandas/numpy
except ImportError:
    ...

# 后：只问「装没装」
if importlib.util.find_spec("yfinance") is not None:
    return
```

单看这一步的成本（同机 hyperfine n=20，均热态）：

| 写法 | 3.9 | 3.14 venv |
|---|---:|---:|
| `import yfinance` | 349.6 ms | 345.5 ms |
| `find_spec("yfinance")` | 23.5 ms | 16.0 ms |

端到端（`/usr/bin/python3 get_data.py --type us --code AAPL`，同一缓存目录，
n=15）：**351.5 ± 13.2 ms → 36.0 ± 0.6 ms**（−90%，9.8×），RSS **81MB → 14MB**。
判据与 `sources/registry.py` 的模块探测一致，本仓本来就有这个正确写法。

能力未降级：`--type us` 仍返回 `quote/financial/analyst/risk/business` 全套
（source=yfinance，走 in-process，无需 re-exec——本机 3.9 也装了 yfinance）。

### 2.2 同花顺搜索结果落盘（`sources/hithink._search`）

`search` 是快照链的**串行前置**：代码 → thscode 的映射几乎不变，但每次快照
未命中都要重付一次。实测单次中位 126–150ms，新连接 591–643ms。

| 场景（每次清掉 `snapshot` 缓存，n=5 取中位） | 不缓存 search | 缓存 search | 节省 |
|---|---:|---:|---:|
| `stock 600519` | 0.58s（0.56–0.61） | **0.44s**（0.41–0.50） | −24% |
| `fund 005827` | 0.60s（0.53–0.79） | **0.46s**（0.43–0.82） | −23% |

四条语义被用例钉住（`test_hithink.py`，离线、0.19s）：

1. 命中后不再发请求；
2. 缓存键含 `asset_type`——股票结果不会答掉基金问题；
3. **空结果不落盘**（「查无此标的」可能是新上市或上游抖动，不钉 24h）；
4. 注入 `http_get` 的单测路径**不读不写**缓存，结论不依赖本机缓存残留。

风险口径：名称 → 代码最坏陈旧 24h；纯代码精确匹配不受影响（`pick_ticker`
先比 thscode 再比 ticker/name）。与 `tencent.search` 的 24h 名称缓存同一做法。

### 2.3 删掉零命中的进程内 L2 缓存

`a1c4923`（10-15）声称「行情 10s 内重复零往返」。实际调用方只有一个：
`cmd_quote.run()`，而 CLI 每进程只跑一条命令后 `sys.exit`——进程内缓存**命中率恒为 0**。
跨进程去重由 `tencent.quote` 自己的 10s 磁盘缓存承担（载荷 `cached: true`）。

删除 `_common.l2_cache_get/set`（25 行）、`cmd_quote` 里的 L2 分支（14 行）；
同时删掉 `_common.eastmoney_api_key`（7 行）——它与 `sources/eastmoney.load_api_key`
是同一件事的两份实现且行为不同（09-22 第四轮遗留 6，至今零调用者）。
`secret_from_file` 保留：它是 `_common` 头注释承诺的公共 API 面。

### 2.4 `zip(strict=True)` 破 3.9（10-17 WIP 的缺陷）

`strict=` 是 PEP 618、3.10 起才有。系统 3.9 下 `TypeError: zip() takes no keyword
arguments`，6 条测试红。改为显式比较长度，行为等价（同样的 `ValueError` 文案）：

- `sources/wind._paired`（基金档案/年度字段/区间收益率三个取数点共用）；
- `sources/wind.fund_nav_series` 的分段结果按位配对处。

## 3. 新增的两道静态门禁

| 文件 | 拦什么 | 为什么测试拦不住 |
|---|---|---|
| `test_static_imports.py` | 用了 `urllib.X` 却没在可见作用域 `import urllib.X`（53 个生产模块逐个对账；含自检：10-07 registry、10-15 hithink 两种形状必须判红） | `ruff F821` 看不见：`urllib` 这个名字是绑定的，缺的是**属性**；两次事故都是适配器把 `NameError` 当「源不可用」吞掉，测试全绿 |
| `test_py39_compat.py` | 生产代码必须能按 3.9 语法解析；禁止 `zip(..., strict=...)` | 3.10+ 语法在 3.14 上永远合法，只有换解释器才暴露；这次正是「6 红两天没人跑」 |

两道门都做了**自检**（把历史 bug 形状喂进去必须判红、把合法写法喂进去必须判绿），
否则门禁本身可能空转。自检实测：注入 `strict=True` → 报红；注入 `match` 语法 → 报红；
`from urllib import parse`、函数内延迟导入、`import urllib.request as _req` 均不误报。

- **`CHANGELOG.md` 停在 v2.9**，而 `SKILL.md` 已是 v3.0（10-13 起就不同步）。
  属于版本号决策，不在本轮。
- **无提交门禁**：`~/.agents/.git/hooks` 仍是空的。`check.py` 建好了但要人记得跑；
  把 `test_py39_compat` / `test_static_imports` 放进 pytest 后，跑一次 check.py 就能拦住
  这两类，但「提交时自动跑」是方向级改动（方案 B），未做。
- **live 用例仍随机器而变**：`test_sec_edgar` / `test_contract` 里有 3 条真实联网用例，
  3.14 下 skip、3.9 下跑，结论取决于网络。未加 marker（同属方案 B）。
- **Token 未动**：本轮未删任何 SKILL 正文（方案 C 未执行），Token 与基线相同。
- **中文名透传（10-17 WIP）实测**：`stock 茅台的` 能取到贵州茅台（走 hithink 名称检索，
  失败时东财模糊匹配），但 `stock 贵州茅台的` 四源全部不命中——上游按名字**整串**

  `NotOpenSSLWarning`（LibreSSL）。`invest_cli.py` 入口已装同一条过滤器，`get_data.py`
  没装。对把 stdout/stderr 合并解析的调用方是个假故障源，修法是一行
  `warnings.filterwarnings(...)`（照抄 invest_cli.py）。属另一个问题，未混进本轮。
